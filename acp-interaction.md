> если я запускаю агента с ACP режимом - как правильно ему передать промпт 

Если ты имеешь в виду **ACP — Agent Client Protocol**, то в этом режиме промпт обычно передаётся **через JSON-RPC вызов `session/prompt`**, а не аргументом командной строки. Агент работает как процесс, с которым общается ACP-клиент.

Для типичного ACP-подключения через `stdio` порядок такой:

1. Запускаешь агента в ACP-режиме.
2. Отправляешь `initialize`.
3. Создаёшь сессию через `session/new`.
4. Передаёшь текст через `session/prompt`, указав полученный `sessionId`.

Пример сообщений, которые клиент отправляет в **stdin агента**. Каждое JSON-сообщение должно быть на отдельной строке.

Инициализация:

```json
{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":1,"clientCapabilities":{}}}
```

После ответа на инициализацию — создание сессии:

```json
{"jsonrpc":"2.0","id":2,"method":"session/new","params":{"cwd":"/absolute/path/to/project","mcpServers":[]}}
```

В ответе агент вернёт идентификатор сессии, например:

```json
{"jsonrpc":"2.0","id":2,"result":{"sessionId":"session-123"}} 
```

Теперь можно отправить промпт:

```json
{"jsonrpc":"2.0","id":3,"method":"session/prompt","params":{"sessionId":"session-123","prompt":[{"type":"text","text":"Изучи проект и объясни, как устроена авторизация."}]}}
```

**`prompt` — массив блоков контента, а не строка.** Для обычного текста достаточно одного блока `type: "text"`.

Во время выполнения агент присылает уведомления `session/update`, в том числе с частями ответа. Завершение хода приходит ответом на `session/prompt`, например:

```json
{"jsonrpc":"2.0","id":3,"result":{"stopReason":"end_turn"}}
```

Следующий промпт отправляется тем же методом с тем же `sessionId` и новым `id`. Клиенту также может понадобиться обрабатывать запросы агента, например на разрешение выполнить действие.

Какого именно агента ты запускаешь и какой командой? Тогда смогу показать точный вариант для твоего запуска.

---

> а если я хочу продолжить сессию?

---

Если подключение к агенту ещё открыто, **отправляй следующий `session/prompt` с тем же `sessionId`** — история сессии сохранится:

```json
{"jsonrpc":"2.0","id":4,"method":"session/prompt","params":{"sessionId":"session-123","prompt":[{"type":"text","text":"Теперь предложи, как упростить авторизацию."}]}}
```

Обычно следующий промпт отправляют после завершения предыдущего хода — когда пришёл ответ на предыдущий `session/prompt` с `stopReason`.

Если **процесс агента был перезапущен или ты подключаешься заново**, сначала выполни `initialize`, а затем восстанови сессию через `session/load`:

```json
{"jsonrpc":"2.0","id":2,"method":"session/load","params":{"sessionId":"session-123","cwd":"/absolute/path/to/project","mcpServers":[]}}
```

После успешного ответа отправляй `session/prompt` с этим же `sessionId`.

Восстановление доступно, если агент объявляет в ответе на `initialize`:

```json
{
  "agentCapabilities": {
    "loadSession": true
  }
}
```

Это фрагмент ответа, а не отдельное сообщение. При загрузке агент может передать историю через уведомления `session/update`.

**Сохрани `sessionId` из ответа `session/new`.** Для продолжения после перезапуска агент должен поддерживать загрузку и хранить сессии между запусками. Если `loadSession` не поддерживается, стандартным вызовом ACP восстановить старую сессию не получится — потребуется механизм конкретного агента либо новая сессия с переданным контекстом.
