## Техническая спецификация

### Стэк

- Python3.12+
- FastAPI, в том числе для отдачи статики
- SQlite в качестве СУБД

Приложение использует серверные Jinja-шаблоны и HTTP API. `templates/index.html` не является самостоятельной страницей для `file://`: ему нужен рендеринг FastAPI. Клиентские скрипты обычные, без ES import и без сборки; локальная библиотека Marked подключается только вместе с чатом.

### Тестовые зависимости

- `requirements.txt` задаёт `httpx>=0.27,<1.0`, `starlette>=1.6.0,<2.0` и `fastapi>=0.141.1,<1.0`. Отдельной зависимости httpx2 в проекте нет; текущий Starlette TestClient умеет использовать установленный httpx через fallback.
- Временное ограничение `anyio>=4.14,<4.15` необходимо из-за обращения Starlette 1.6.0 к `anyio.abc.BlockingPortal`. Это ограничение совместимости, а не исправление устаревшего API внутри Starlette; пересмотреть после выхода её исправленной версии.
- Контрольный прогон: `PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=. dev-venv/bin/python -m pytest -q -p no:cacheprovider -W error tests`. Предупреждения не подавлять.
- В тестах удалённого удаления подменять ссылку `board_store.Config` локальным объектом конфигурации, а не общий метод класса `Config.get`. Это сохраняет реальные default-значения настроек для lifespan, включая `tasks.logs_max_age`, и не отключает очистку логов ради прохождения тестов.

### Жизненный цикл приложения

- Инициализация SQLite выполняется до обработки запросов через `FastAPI(lifespan=...)`; устаревший `on_event("startup")` не используется.
- В том же lifespan после инициализации БД выполняется `log_cleanup.cleanup_session_logs`: однократная очистка `data/logs` по `tasks.logs_max_age` (default `86400` секунд), до запуска proxy listeners. Возраст определяется по mtime, сравнение строгое. Очистка не рекурсивная, не следует символическим ссылкам и сохраняет скрытые файлы. Отсутствующий каталог допустим; ошибки доступа/удаления записываются в warning и не мешают запуску и обработке остальных файлов.
- Проверки очистки: `tests/test_log_cleanup.py` — граница возраста, ноль, безопасная область удаления, ошибки файловой системы, startup, default и сохранение/валидация настройки. Совместно с `test_app.py` и `test_settings_regressions.py` — 40 passed. Playwright проверил default, integer input, Save/reload и отсутствие переполнения на 375px; форма визуально сверена с `settings_proto.png` на 1357px и проверена на мобильной ширине.
- Повторный запуск жизненного цикла безопасен: существующие таблицы и данные сохраняются. Проверка — `tests/test_app.py::test_lifespan_initializes_database_without_deprecation`.
- HTTP reverse proxy запускаются и останавливаются в том же lifespan через `http_proxy.ProxyServers`. Каждый listener независим: ошибка запуска видна на вкладке HTTP proxy и не прерывает основное приложение.
- После успешного Save секции HTTP proxy контроллер вызывает `ProxyServers.apply_policies`: по неизменному порту заменяется единый снимок методов и скомпилированных паттернов, без остановки listeners, пула соединений и активных SSE. Полный цикл Save сериализован отдельным lock этой секции. Добавление/удаление, port, remote URL и timeout остаются отложенными до перезапуска; API возвращает `restart_required` для Toast.
- `start.py` передаёт фактические `--host`/`--port` web-процессу через `APP_WEB_HOST`/`APP_WEB_PORT`. При прямом CLI-запуске Uvicorn обработчик читает параметры запуска. Для программного запуска адрес можно передать этими переменными окружения.
- Потоковый транспорт прокси — `httpcore>=1.0,<2.0`, явный сырой request target без нормализации URL, без cookie jar и декомпрессии. Проверки доступности настроек используют HTTPX. Отключение проверки TLS ограничено HTTP proxy; остальные соединения не меняются. Требования — [http-proxy.md](http-proxy.md).

### Цикл запуска задачи

Нормативные требования: запуск и Init — [agent.md](agent.md), поля Tasks — [settings.md](settings.md), фазы — [board.md](board.md), диагностика — [task-chat.md](task-chat.md).

- `task_init.py` — отдельный SSH-канал Bash, общий resolver пути, ограничение/санитизация двух потоков, таймаут, остановка группы процессов. На удалённой POSIX-машине требуются Bash, `setsid` с поддержкой `--wait`, `ps`, `awk` и стандартные `kill`/`sleep`. PTY не используется. UTF-8 текст идёт через stdin; временный файл скрипта не создаётся. `setsid --wait` сохраняет фактический код завершения Init и при fork из SSH-процесса — лидера группы.
- Супервизор сообщает PID группы и ждёт подтверждения приложения до выполнения пользовательского скрипта. При отмене отдельный канал посылает TERM/KILL и проверяет отсутствие живых участников группы; zombie уже не выполняет код. Ошибка проверки считается неподтверждённой остановкой.
- Base directory (`tasks.base_dir`) — обязательный редактируемый родительский каталог задач. Создание и удаление используют его нормализованный путь; Init и ACP запускаются в дочернем каталоге `<TASK-ID>`. Автоматический корень хранения не используется.
- `agent.shell` допускает обычную ACP-команду без `${PROMPT}`. Промпт передаётся через `session/prompt` после `session/new` или `session/load`; необязательная shell-подстановка сохраняется для совместимости. Регрессия `tests/test_agent_remote.py::test_acp_shell_without_prompt_placeholder` проверяет оба сценария и отсутствие текста промпта в команде.
- `task_cycle.py` — сохранение фазы, готовности/принадлежности каталога, результата Init и проверка актуального run_id. `agent_store.py` сохраняет результат Init отдельно от ACP; `board_store.py` мигрирует старые БД, добавляя поля цикла и роль system в чат без удаления истории.
- `settings/validation/tasks.py` — проверка Init; `settings/locking.py` — межпроцессная блокировка снимка/сохранения конфигурации (POSIX и Windows). Production `venv` не используется тестами.
- Регрессии: `tests/test_task_init.py` (включая настоящий Bash без внешнего SSH), `tests/task_cycle_ui.js` (реальный FastAPI/SSE в изолированной БД и настройках). Браузерные тесты запускаются после установки `requirements.txt` в `dev-venv`.

### Каталог требований задачи

`task_context.py` содержит английский стартовый промпт и подготовку `requirements-${TASK_ID}` внутри рабочего каталога задачи. `agent_remote.py` записывает туда `TASK.md` и все вложения через SFTP до Init. Cwd Init и ACP остаётся `<tasks.base_dir>/<TASK-ID>`. Создание контекста эксклюзивное; конфликт отображается в чате как `Task directory requirements-${TASK_ID} already exists.` При каждом запуске, включая повтор с учтённым контекстом, `task_context.sync_context` обновляет описание и все вложения и удаляет устаревшие обычные файлы из каталога требований; файлы вне него сохраняются. Symlink и вложенные каталоги требований отклоняются до записи. Ошибка синхронизации блокирует Init/ACP. Проверяются нормализация путей и запрет symlink.

Нормативная структура каталогов, точный промпт и таблица первого/повторного запуска — [agent.md](agent.md); доступ к контексту из Init — [settings.md](settings.md#tasks-инициализация-каталога); текст и история ошибки — [task-chat.md](task-chat.md#конфликт-каталога-требований).

### Явная отмена ACP

- `process_scope.py` формирует идентификатор машины/ОС и Linux PID namespace; `agent_runs.executor_scope` сохраняется при захвате. `agent_store.recover` и `agent_launcher.launch` не проверяют и не завершают чужие PID. Для legacy-записей без scope предусмотрена проверка совместимости формата process_token с ОС. Recovery просроченного чужого запуска требует среды его владельца; отсутствие PID на другом хосте не доказывает смерть процесса.
- Подтверждение остановки в `TaskCycle.agent_stopped` согласует флаги задачи и запуска. `agent_store.finish` не устанавливает неопределённость поверх нового `agent_stop_confirmed=1` по устаревшему снимку recovery. Проверки разных сред, локальной смерти и обоих порядков гонки — `tests/test_executor_scope.py`.

- `agent_control.py` — супервизор группы `setsid --wait`, проверка `ACP_PID`/`GO`, сериализация записи ACP и отправка `session/cancel` без `id`. Использует остановку и проверку группы из `task_init.stop_group`.
- `agent_remote.py` опрашивает принадлежность запуска задаче каждые 100 мс. После обнаружения отмены ждёт не более 60 секунд, включая возможную блокировку отправки уведомления. После ответа или истечения срока останавливает группу и закрывает SSH; до отправленного prompt ожидание не требуется.
- Миграции сохраняют существующие записи: `agent_runs` получает `agent_pid`, `cancel_requested_at`, `agent_stop_confirmed`, `agent_uncertain`; `board_tasks` — `agent_uncertain`. Пока старый запуск активен, монопольная очередь занята. Неподтверждённая остановка блокирует захват всей очереди до ручного подтверждения. Recovery учитывает 60 секунд отмены плюс 20 секунд очистки.
- Отменённый запуск сохраняет `FAILED`/`cancelled`, системную диагностику и прежний sessionId. Сохранённый BACKLOG и новый запуск защищены от поздних результатов старого run_id.
- Регрессии: `tests/test_agent_cancel.py` запускает реальные локальные ACP-процессы и потомков через имитацию SSH; `tests/agent_cancel_ui.js` запускает изолированный FastAPI, проверяет обе формы и полный 60-секундный предел с агентом, игнорирующим отмену. Временные базы, скрипты тестового агента и процессы очищаются фикстурами.

- `controllers/agent.py` обслуживает GET/POST `/api/agent/recovery` для кнопки Agent Recovery на Board. POST принимает `run_id` и вызывает транзакционный `agent_store.confirm_remote_stop` после подтверждения оператора в UI; CLI-файл удалён. `static/js/agent-recovery.js` — отдельный обычный script без сборки и import. Активные/неизвестные/уже подтверждённые запуски отклоняются. Обработчик сохраняет историю, не меняет статусы задач и не снимает блокировки других запусков. При блокировке claim журнал сообщает TASK-ID и run_id, чтобы очередь не простаивала без диагностики. Проверки — `tests/test_agent_recovery.py`.

### Ложное отклонение sessionId — 2026-09-24

Проверка ответа `session/new` использовала потоковый фильтр `_Diagnostics.safe`, маскирующий даже один последний символ при совпадении с началом SSH-секрета или PEM-маркера. Корректные случайные идентификаторы поэтому периодически отклонялись с `Missing, invalid or unsafe sessionId`, включая замену отсутствующей сессии после `session/load`.

Для целого JSON-поля используется `safe(..., partial_suffix=False)`: полные известные секреты и PEM-блоки по-прежнему отклоняются, неполные суффиксы не маскируются. Передаваемый в callback и `session/prompt` ID сохраняется без изменения. Потоковая диагностика и чат используют прежнюю защиту по умолчанию.
