## Раздел Archive

Пункт меню web-app: Archive

Представляет собой список задач, перенесённых в статус `ARCHIVE`.

### UI

- На странице не добавлять декоративные или текстовые заголовки раздела, если они явно не предусмотрены отдельным макетом.
- Задачи отображаются списком, постранично.
- На одной странице отображается не более 20 задач.
- Для перехода между страницами отображаются элементы пагинации.
- Если архив пуст, отображается состояние пустого списка без ошибок.
- Для каждой задачи отображаются как минимум:
  - идентификатор задачи (`%TASK-ID%`);
  - название задачи (`%TASK-TITLE%`);
  - дата создания;
  - статус `ARCHIVE`.
- При обычном клике (также Enter/Space) открывается отдельная страница `/tasks/<TASK-ID>` в текущей вкладке; модального окна Archive нет. Активным остаётся меню Archive. Поля и удаление вложений заблокированы, загрузка новых файлов отсутствует, Save и Cancel не отображаются. Доступна кнопка Delete с подтверждением; история чата показывается при наличии сообщений, поле комментария скрыто.
- При клике с ctrl (cmd) задача открывается в новой вкладке.
- Ошибки загрузки и действий пользователя отображаются через Toast согласно [main_ui.md](main_ui.md).

### Алгоритм работы

- В список Archive попадают только задачи со статусом `ARCHIVE`.
- При открытии страницы загружается первая страница архива.
- Каждая следующая страница загружает следующую группу из 20 архивных задач.
- Порядок задач: `created_at DESC, id DESC`, то есть по дате создания, а не по времени архивирования; при одинаковой дате первыми идут большие внутренние ID.
- Переход в `ARCHIVE` разрешён только из статусов `BACKLOG`, `WAIT` и `DONE`.
- Переход из `ARCHIVE` в любой другой статус через пользовательский интерфейс не допускается.
- Архивные задачи не отображаются в колонках Board.

### Пагинация

- Размер страницы фиксирован: 20 задач.
- Номер страницы начинается с 1.
- Для страницы `N` возвращаются задачи с offset `(N - 1) * 20` и limit `20`.
- Для положительного номера за пределами списка API возвращает пустой список, UI показывает `Archive is empty`; автоматического перехода на последнюю страницу нет. Номер менее 1 или нецелый номер отклоняется с 422.
- Пагинация должна быть доступна с клавиатуры и иметь понятные подписи/ARIA-атрибуты.

### Данные задачи

Archive использует общую модель задачи Board:

- `%TASK-ID%` — уникальный идентификатор задачи.
- `%TASK-TITLE%` — название задачи.
- `Текст задачи` — описание задачи.
- `Статус задачи` — `ARCHIVE`.
- `Дата создания` — формат `ГОД-МЕСЯЦ-ДЕНЬ ЧАС:МИНУТА`.
- `Файлы` — вложения задачи, хранящиеся в файловой системе в папке [files](../data/files).

Источник данных — СУБД проекта.

### Окончательное удаление

- `DELETE /api/archive/tasks/{task_id}` разрешён только для архивных задач; иначе возвращается 404 без подключения по SSH.
- Сначала подключиться по SSH с настройками `remote_server.*` и удалить каталог `<TASK_ROOT>/<TASK-ID>` со всем содержимым через SFTP. Использовать доверенные host keys, приоритет SSH-ключа над паролем и таймауты подключения/операций.
- Только после подтверждения отсутствия удалённого каталога удалить задачу и записи вложений из БД, затем локальные файлы вложений. Конкурирующие изменения БД блокируются транзакцией на время удаления.
- Любая ошибка конфигурации, подключения, проверки пути или удаления (в том числе частичного) возвращает 502: задача, записи вложений и локальные файлы сохраняются. Ошибка отображается существующим Toast без раскрытия секретов.
- Уже отсутствующий каталог считается успехом только после подключения и получения SFTP-ошибки ENOENT. Ошибки доступа не считаются отсутствием.
- Каталог задачи должен быть непосредственным потомком нормализованного `TASK_ROOT`; небезопасные ID и корневые символьные ссылки запрещены. Вложенные символьные ссылки удаляются как ссылки, без обхода их целей.
- При успехе API возвращает 204. Ошибки запуска агента по-прежнему не удаляют удалённые каталоги автоматически.


`TASK_ROOT` — нормализованный путь из настройки `tasks.base_dir` (Base directory), как при запуске задачи; см. [agent.md](agent.md). Удаление использует этот каталог и не создаёт его.

### Границы режима просмотра

Запрет редактирования архивной задачи реализован в UI. Общий `PUT /api/board/tasks/{task_id}` допускает изменение названия, описания и вложений при сохранении статуса `ARCHIVE`; переход в другой статус он запрещает. Имена вложений в форме выводятся текстом, без ссылок, хотя endpoint скачивания существует.

После окончательного удаления история чата удаляется каскадно, записи `agent_runs` сохраняются с `task_pk = NULL`. Локальные файлы удаляются после COMMIT: ошибка их удаления уже не откатывает удаление задачи и не относится к гарантии сохранения БД при ошибке SSH.
