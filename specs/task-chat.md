## Состояние и комментарии к задаче

См. прототип дизайна ![task-chat-status.png](task-chat-status.png)

Виджет статусов и комментариев справа отбражается только для всех статусов (если есть по нему данные).

Область сообщений автоматически прокручивается к последнему сообщению только при получении нового статуса агента или изменении его текста/даты-времени, независимо от текущей позиции прокрутки. Первичная загрузка истории, опрос без изменений, комментарии пользователя и смена состояния задачи сами по себе не запускают автопрокрутку.

Сообщение "%model responce%" - это последнее актуальное сообщение от удаленного агента. В случае если задача IN PROGRESS - тут необходимо отбражать в реальном времении
последний ответ агента (пример формирования ответа см. в [test_remote_agent.py](../test_remote_agent.py)). В пределах одного запуска (`run_id`) предыдущий ответ агента заменяется новым, а не добавляется в этот виджет. При отправке комментария и перезапуске задачи последний статус каждого предыдущего запуска сохраняется вместе с его датой-временем. Новый запуск формирует отдельный статус; история отображается в порядке создания сообщений, включая комментарии пользователя. Для каждого сообщения отображается дата-время его последнего обновления в формате `ГГГГ-ММ-ДД ЧЧ:ММ`.


Сообщение "%user comment%" - комментарий пользователя из поля ввода "user comment". Поле ввода комментария отображается только в статусах:
- REVIEW
- WAIT

Комментарий пользователя также содержит дату-время отправки в формате `ГГГГ-ММ-ДД ЧЧ:ММ`.
При нажатии "Send comment" отправляется комментарий, обновляется виджет статусов и комментариев, задача переводится в OPEN.
Если у задачи есть комментарий от пользователя, то меняется алгоритм запуска задачи:
- комментарий пользователя помещается в плейсхолдер "${PROMPT}" 
- параметра запуска агента agent.shell, к agent.shell добавляется параметр cli, заданный в поле continue_session_arg

При наличии комментария resume переиспользует существующий безопасный рабочий каталог и не перезаписывает `TASK.md` или вложения; первый запуск создаёт каталог исключительно через `mkdir`. Путь нормализуется и проверяется как непосредственный каталог внутри `tasks.base_dir`, включая запрет symlink escape. Комментарий передаётся в `${PROMPT}` как один `shlex.quote`-аргумент, а trusted `agent.continue_session_arg` добавляется к shell-команде.

ACP `agent_message_chunk` накапливается, после каждого безопасного полного accumulated-текста вызывается optional callback; thoughts/stderr callback не получают. Диагностика санитизируется по полному накопленному тексту, поэтому секреты, разделённые chunk-ами, не раскрываются.

Обновление Board выполняется SSE polling-снимками каждые 500ms; task chat остаётся отдельным endpoint GET/POST `/api/board/tasks/{task_id}/chat`. Комментарий принимается атомарно только для `WAIT`/`REVIEW`, переводит задачу в `OPEN`; duplicate/invalid requests возвращают 409/422. Ошибка агента переводит задачу в `WAIT` с признаком ошибки.
